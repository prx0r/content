# PowPowPow as knowledge compiler (spec)

> UKGraph content = graph → anomaly. PowPowPow content = graph →
> concept / relationship / thesis / anomaly.

## Channel identity

> "We explain where AI, compute, energy, crypto and physical
> bottlenecks intersect."

Broader and more durable than "crypto content", still clickable:
Qubic, XMR, quantum resistance, HBM, GPUs, mining economics, power
constraints, AGI infrastructure.

## Three content modes

```text
1. EXPLAINERS
"What is Qubic?" / "Why does HBM matter?"
"Why is Monero important in an AGI world?"

2. SIGNALS
"Qubic compute economics just changed."
"This network is now paying X per watt."

3. THESIS / MAPS
"AI → HBM → packaging → power → mining"
"Which assets sit on physical bottlenecks?"
```

One node produces a family: explainer, comparison, economics,
AGI angle, hardware angle, signal. Same graph, different templates.

## Canonical primitives (Signal plus three)

```text
Concept
Relationship
Thesis
Signal
```

Content MCP queries:

```text
GET /concepts/qubic/explain
GET /concepts/xmr/why-now
GET /relationships/ai-demand/hbm
GET /theses/privacy-in-agi
GET /signals/top
```

One strong relationship becomes: short, thread, article, chart,
explainer, comparison, watchlist, API/Muse answer.

## Analytical-framing rule

Never direct financial recommendations. "Buy these quantum-resistant
coins" becomes "Which projects claim quantum resistance, and how do
their approaches differ?"

## Architecture answer

/content is the pure engine MCP (intent + graph + contracts +
receipts). PowPowPow, UKGraph, and others feed it signals, concepts,
theses — or agents call it directly for whatever content. Gardens own
their facts; the engine owns compilation.
